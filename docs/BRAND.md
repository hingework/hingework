# Hingework brand specification

Status: locked, owner-directed decisions. This is the canonical record for later README, asset, and launch work.

## 1. Brand identity

The project name is **Hingework**. Its identity is evidence-driven escalation: a local/cheap attempt, deterministic evidence validation, mechanical escalation only when trusted evidence checks fail, bounded attempts, and a preserved trail.

The hinge metaphor represents a conditional pivot. Token/cost savings are a benefit, not the primary identity. This keeps the brand centered on the decision mechanism rather than a particular provider or model hierarchy.

## 2. Locked copy

Preserve these lines verbatim, including punctuation:

- **Primary positioning:** Escalate models when evidence checks fail—not when a model feels uncertain.
- **Secondary:** Every handoff hinges on hard evidence.
- **Playful secondary:** Help with work, without the guesswork.
- **Support:** Local first. Deterministic validation. Bounded escalation. Preserved trail.

The primary line states the technical distinction. Secondary copy supports that distinction; it must not replace or weaken it. “Hard evidence” refers to the trusted deterministic checks, not a guarantee of semantic correctness.

## 3. Logo direction

**Hinge H** is the static primary logo: a rigid geometric "H" built around the hinge/pivot metaphor.

- Flat vector construction with a monochrome core.
- Structural/mechanical feel, using the pivot/hinge metaphor.
- No literal hardware realism.
- The static mark remains the primary logo.

The geometry should express a controlled pivot while keeping the identity recognizable without animation or semantic color.

## 4. Hero direction

**Terminal Pipeline** is the locked direction: a literal architecture/process explanation.

- Show the local-first attempt and a deterministic evidence checkpoint that visibly controls escalation.
- **PASS returns:** passing evidence checks end the escalation path and return the result.
- **Trusted evidence failure escalates:** advance only when the trusted validator rejects the evidence and a configured attempt remains.
- **Operational/provider error stops:** an error is not an evidence verdict and must not be drawn as an escalation trigger.
- Show bounded attempts and a stop when the available attempts are exhausted.
- Show the preserved trail across attempted results.

The hero explains the actual control flow. It must not suggest that every request climbs to the strongest model or that model confidence controls the checkpoint. Technical behavior and limits remain governed by [DECISIONS.md](DECISIONS.md); this brand record does not expand them.

## 5. Visual rules

- Use strict flat/vector design: no gradients, shadows, or fake depth.
- Maintain high contrast.
- Treat GitHub dark mode as first-class and fully support light mode.
- Keep the logo monochrome.
- Use semantic accent colors only in diagrams, hero visuals, and state visuals.

These rules support legibility across both themes and reserve color for process meaning.

## 6. Motion-asset rule

An optional **H → W** hinge animation derived from the static **Hinge H** mark is a secondary motion asset only. The motion asset does not replace the static primary logo or carry meaning required to recognize the brand or understand the process.

The static identity must remain complete on its own.

## 7. README / README_ADHD presentation rules

README presentation uses the locked name and copy, the static primary logo, and the Terminal Pipeline direction when a hero is included. Examples and claims must agree with the existing technical closeout; brand presentation does not establish new commands, package availability, or capabilities.

`README_ADHD.md` is a real companion document, not a joke file. Optimize it for rapid scanning and reduced cognitive load through short sections, strong hierarchy, whitespace, and code-first examples.

Companion visual assets may use a high-legibility typeface such as Atkinson Hyperlegible / Mono. GitHub controls Markdown typography; do not represent a custom font as guaranteed in the rendered README.

Do not claim that any font is scientifically proven to treat or help ADHD. The rationale is clear, scannable presentation without medical claims.

## 8. Prohibited claims and metaphors

Do not use:

- Chess pieces, crowns, kings, queens, or pawns.
- Humanoid robots, glowing brains, generic neural-network imagery, AI swarm imagery, or agents around a table.
- Copy or visuals implying confidence-based or model-self-assessment-based escalation.
- Visuals implying endless or inevitable progression toward a strongest model.
- Unsupported token, cost, or performance claims.

These exclusions protect the evidence-driven identity and prevent unsupported interpretations of the system.
